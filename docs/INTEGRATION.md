# Integrating with Bolina

Bolina is a capability-based intent protocol node. Applications do not
speak the UDP wire protocol: the daemon is the protocol endpoint. Your
application talks **local HTTP** to the daemon's control plane and deals
only in semantics: intents, grants, events.

```
+----------------+        HTTP 127.0.0.1:7421       +-----------------+
|  your app      |  ------------------------------>  |  bolina daemon  |
| (any language) |   POST /v1/intents, GET events    |  UDP wire :7420 |
+----------------+                                   +-----------------+
```

Any runtime that can open a TCP connection can integrate: Python, Rust,
Node, Go, Java, C#, PHP, curl, a shell script. No SDK required.

## 1. Boot a node

```sh
export BOLINA_BIND=0.0.0.0:7420          # UDP wire endpoint (protocol peers)
export BOLINA_DATA_DIR=~/.bolina         # keys, ledger, cert, control token
export BOLINA_CONTROL=127.0.0.1:7421     # opt-in HTTP control plane (loopback)
export BOLINA_RESOURCES="bol:<fp>/<ns>/<id>,bol:<fp>/<ns>/<id2>"
./zig-out/bin/bolina
```

On first boot the node generates its X25519/Ed25519 key material
(`0600` files under `BOLINA_DATA_DIR`) and prints:

- its **identity fingerprint** (16 hex chars) once, and
- the **control-plane bearer token** once (`control.token`, mode `0600`).

`BOLINA_RESOURCES` declares every resource id this executor will admit
intents for, in canonical form `bol:<node_fp_hex16>/<namespace>/<id>`.
The fingerprint must be **this node's own** (foreign fingerprints are
rejected at admission). Malformed entries are fatal at boot; an absent
declaration admits nothing (fail-closed).

## 2. Issue the node's certificate (real deployments)

Test/dev boots run without a certificate (unbound-accept mode). For real
peering, issue one from your offline CA:

```sh
./zig-out/bin/bolina ca init   --dir /path/ca --count 2
./zig-out/bin/bolina ca issue  --ca-dir /path/ca --node-dir ~/.bolina \
                               --role executor --name my-node \
                               --scope <resource_id_hex32> --ttl 24h
./zig-out/bin/bolina ca list   --ca-dir /path/ca
./zig-out/bin/bolina ca show   --ca-dir /path/ca --serial <hex>
./zig-out/bin/bolina ca revoke --ca-dir /path/ca --serial <hex> \
                               --subject-expiry-ms 86400000 \
                               --out /path/ca/rev/<serial>.revoke
```

Notes: `--scope` takes raw hex bytes of the resource id (repeatable, up
to 8). Certificate lifetimes are capped (BE-REV-01); revocation
envelopes carry the subject's own expiry (BE-CTRL-03). The `--out`
parent directory must exist. Distribute `ca/*.pub` as trust anchors to
every peer and restart nodes to pick them up.

## 3. Talk to the control plane

Full machine-readable contract: [`openapi.yaml`](openapi.yaml).
Working client: [`examples/intent_client.py`](examples/intent_client.py)
(stdlib only).

| Endpoint | Auth | Meaning |
|---|---|---|
| `GET /healthz` | none | liveness ("bolina ok") |
| `POST /v1/intents` | bearer | submit an intent for admission |
| `GET /v1/events?since=N` | bearer | SSE stream of ledger events after seq N |
| `GET /metrics` | bearer | Prometheus counters |

Submit an intent:

```sh
TOKEN=$(cat ~/.bolina/control.token)
curl -s -X POST http://127.0.0.1:7421/v1/intents \
     -H "Authorization: Bearer $TOKEN" \
     -H 'Content-Type: application/json' \
     -d '{"intent_id":"<32 hex chars, generated by you>",
          "resource_id":"bol:<fp>/<ns>/<id>",
          "action":"read","rationale":"nightly report"}'
```

Status codes: `202` admitted (an exact retry of the same `intent_id`
while it is still pending is also `202` and is not double-counted),
`409` resource already held by another pending/executing intent,
`422` unknown or foreign resource, `400` malformed body, `403` bad or
missing token, `501` unsupported transfer encoding.

Consume events: `GET /v1/events?since=<last seen seq>` returns
`text/event-stream`; each `data:` line is a JSON object with at least
`seq` and `kind`. Reconnect with the highest `seq` you processed.
The ring keeps the most recent 256 committed events; older cursors
replay from the oldest retained entry.

## 4. Ground rules

- The control plane binds loopback only. Remote access is a deployment
  decision outside v0.6 scope; do not expose it without reading
  THREAT-MODEL.md first.
- HTTP can never mutate grants or the ledger directly. Admission goes
  through the same resolver and table the wire path uses; there is no
  god-mode endpoint.
- `/healthz` is intentionally unauthenticated (liveness probes); every
  other path requires the bearer token, verified constant-time.
- Token rotation = delete `control.token` and restart the daemon.
